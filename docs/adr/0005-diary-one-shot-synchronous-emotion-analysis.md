# 情绪日记分析采用提交时同步一次性分析

情绪日记的 AI 分析选择在 POST /emotion-diary 内同步执行：保存 → LLM 分析 → 落库 → 响应携带完整结果。这与会话情绪分析的懒计算+缓存（ADR-0004）刻意不同：日记内容提交后不可变，分析没有"失效重算"的语义；且危机场景（riskLevel=3）下"用户还在页面上"是 12356 红卡唯一的交付窗口，异步分析的红卡永远无人看到。分析失败不阻塞日记保存，`aiEmotionAnalysis` 置 null 且不自动重试。

## Considered Options

- 异步分析（提交即返回，后台落库）：被否决——用户提交完关页，危机红卡延迟到无人接收；需后台任务机制。
- 懒计算+缓存（读详情时才分析）：被否决——日记不可变，无缓存失效条件，懒计算退化为"首次读分析一次"；且红卡同样延迟到用户主动回看。
- 提交时同步一次性分析：红卡当场交付；日记素材短（≤3000 字）耗时可控；与"提交后不可变"模型自洽。

## Consequences

- POST 接口耗时 = LLM 耗时（数秒级），前端需复用 60s 超时的先例。
- LLM 输出结构复用会话分析的 EmotionAnalysisResult（含 riskDescription、improvementSuggestions），但 prompt 为日记专属素材（自评情绪分、触发因素、感想、睡眠/压力指标），非对话消息。
- 用户端完整展示分析结果（含风险等级与红卡），与管理端详情弹窗字段一致。
- ~~分析失败 = 永久缺失该日记的分析（不重试）；管理端详情对 null 已有兜底显示。~~ → 2026-09-07 修订：失败是瞬时的（LLM 超时/限流），而日记素材已冻结——允许用户在详情中对 null 分析手动重试（POST /{id}/analysis/retry）。核心不变量保持不变：**已有结果永不重算**（重试是失败恢复，不是失效重算；实体前置校验 + SQL is-null 条件双重保证并发下不覆盖已有结果）。危机恢复是重试的额外收益：危机日记分析失败时，重试能重开 12356 交付窗口。
