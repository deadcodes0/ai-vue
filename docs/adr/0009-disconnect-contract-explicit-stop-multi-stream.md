# 断连契约、显式停止与单活跃流不变量下沉

刷新绕过导航锁的实测暴露两个事实：单活跃流只是前端内存布尔值，系统并未执行；断开后回复仍生成并落库，靠的是取消信号未传播到内层订阅的偶然容错。本决定确立三条契约并废止导航锁：**①断开不取消**——SSE 连接只是观察窗口，生成与落库的生命周期独立于连接，断开（刷新/关页/断网）后回复继续生成并完整落库；**②停止是显式命令**——用户停止走独立接口，后端在途注册表定位并终止流，已生成部分（残句）作为该次回复的最终形态落库，无中断标记，与自然完成无异；**③单活跃流不变量下沉后端**——同一用户同一时刻至多一条活跃回复，由后端守卫执行，刷新与双开标签页均绕不过；导航自由（切换/新建/删除不再被生成状态拦截），发送锁全局，想走即停（停止按钮）作为等待的解药。多流分区（每会话至多一条活跃回复）列为文档化升级路径，本次不实现。

## Considered Options

- 维持现状（前端导航锁 + 刷新暗门）：否——约束不被系统执行，词汇表声称的不变量系统不维护；同会话双流单标签页即可触达，消息与记忆交错落库。
- 多流分区（每会话一条流，导航与发送均自由）：推迟而非否决——产品上心理支持对话天然串行，停止按钮已吸收"想走就走"的痛点，多流超出产品必需；但其地基（在途注册表）随停止一并建成，未来升级只剩状态查询、轮询可见性与按会话键控的策略调整。
- 断开即取消 + doFinally 部分落库：否——"用户刷新导致内容被截断"语义古怪；部分落库只属于显式停止与超时路径。
- 残句带中断标记 / 丢弃残句：否——丢弃使用户消息悬空（落了库却无回应），对话记忆重建后上下文畸形；标记引入新字段并给记忆重建、情绪分析、会话预览三个消费方各添分支，收益存疑。

## Consequences

- 后端在途注册表按 userId 键控（复用 ADR 0004 已验证的 ConcurrentHashMap 去重模式），职责三合一：新流守卫（已有活跃回复时发起返回 409）、停止命令的定位句柄、活跃状态查询（前端刷新后恢复锁定态、会话列表"生成中"徽标）。取消传播仅为停止/超时显式接线（dispose 流句柄），断开路径保持不接线——"断开容错"从偶然变为有意的不作为，须防回归。
- 前端 `isAiTyping` 语义收窄为"本用户有活跃回复"，仍为单值；导航锁（切换/新建/删除拦截）全部移除，输入锁保留。
- 删除带活跃回复的会话：删除优先，终止在途回复且残句不落库——与软删除"会话退出业务流程、不接受新消息"的既有定义一致。
- 活跃回复有最大时长（建议 120s），超时按停止语义处置（残句落库）并释放槽位。
- 停止与断开在传输层同为连接断开，故停止不可依赖连接事件实现，只能走显式命令；停止瞬间与自然完成的竞态以 doFinally 幂等化解。
- 情绪分析的 done 事件触发在断连/停止场景失效，但 ADR 0004 的懒计算+缓存使其自愈：回复落库使快照过期，下次 GET 重新分析。
- 落库仍发生在完成/停止时刻而非流式过程中：切回正在生成的会话，看到的是"用户消息 + 生成中指示"，回复完成后整条出现；半截不可见是已知且已解释的限制，轮询刷新与多流分区为未来工作。
- 实现清单（单里程碑）：在途注册表 + per-user 守卫 + 停止接口 + 断连契约化（显式不接线 + 防回归注释/测试）+ 导航解锁 + 活跃状态查询。

Status: 取代 ADR 0008 的导航锁部分；0008 中闭包捕获写入目标、done 事件绑定流所属会话、新建会话清空消息区等修复继续有效。
