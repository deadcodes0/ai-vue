# 重连观看：活跃回复的观察流改为可重放 sink

ADR 0009 把"切回生成中会话只见占位符、回复完成后整条出现"列为已接受限制、续看列为未来工作；本次将其落地并顺带消除两处既有脆弱性。观察流从 `Flux.create` 冷桥接改为挂在 ActiveReplyHandle 上的 `Sinks.many().replay().all()` 热流：**发射**（内层 LLM 链）与**观看**（0..n 个 SSE 订阅者）生命周期解耦，断开只减少一个订阅者——契约"断开不取消"由 sink 语义原生成立，不再依赖"发射进虚空"的偶然行为；迟到订阅者收全量回放后接实时流。前端点入生成中会话（刷新后重进，或本标签页切回但无本地流对象）改走 attach：`POST /stream/attach/{dbSessionId}`，事件结构与 `/stream` 完全一致。附带两个修正：冷流可重入地雷（重复订阅=重复 LLM 调用+用户消息重复落库，此前仅靠"一次响应一次订阅"的外部不变量防护）随热流消除；`delayElements(50ms)` 人为节流删除（它会把回放追赶拖成慢动作、给正常观看平添延迟）。

## Considered Options

- 维持现状（占位符 + 3s 轮询）：否——体验最弱一环恰在价值最高的场景（生成中切回/刷新后重进）；注册表句柄已具备锚点，剩余成本集中于一个 sink + 一个端点，"多流分区才是续看地基"的旧判断不成立。
- 流中周期性部分落库 + 前端轮询半截：否——咨询消息从追加式变为可变行，与记忆重建、情绪快照过期语义（ADR 0004/0005）冲突，DB 写放大换轮询延迟，全面劣于回放。
- `multicast().directBestEffort()`（仅实时尾部）：否——迟到者永久丢失前半截，重连体验断裂；且 multicast 系默认 autoCancel（全部订阅者离开即清缓冲并拒绝新订阅者），断连间隙本身即废掉重连。
- `replay().all()`：采纳——单条回复 ≤120s、几十 KB 量级，随句柄释放被 GC，"无界缓冲"担忧不成立；完成瞬间的迟到者天然收到"全量回放+done"，扑空窗口收窄到 release 与 complete 之间的纳秒级间隙。

## Consequences

- 三条既有契约（断开不取消 / 停止是显式命令 / 单活跃流 per-user）不变；被替换的仅是 ADR 0009 的"半截不可见"后果。生成启动时机从"WebFlux 订阅外层流"提前到"Flux.defer 内服务方法调用"（仍与 claim 原子于订阅时刻），原订阅者经 replay 无损。
- 观察流由句柄持有：claim 时即存在，attach 是只读订阅、不触碰槽位；停止/超时/完成统一 emitComplete——跨标签页停止的 done 传播从单连接补救变为原生多播。多标签页并发观看为机制副产品，不作产品承诺（双 done 触发情绪分析由 ADR 0004 懒计算 + Future 去重吸收）。
- 发射失败忽略：tryEmitNext 撞 FAIL_TERMINATED（停止已 complete sink 而分片在途）为良性竞态，分片丢给已终止流无害。
- attach 契约：404（无活跃回复或不属于该会话）是正常扑空信号，前端回退 refreshSessionView 拉库；刷新恢复（restoreActiveReply）仍用 /stream/active + 轮询维护锁态与徽标——attach 只在点入生成中会话时发起。
- 落库仍发生在完成/停止时刻而非流式过程中（不变）；多流分区（每会话一条活跃回复）仍为文档化升级路径。

Status: 修订 ADR 0009 的"半截不可见"后果与"轮询刷新"未来工作项；0009 三契约本体不变。
