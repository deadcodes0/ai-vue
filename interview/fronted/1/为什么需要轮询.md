这段代码是**"活跃回复状态"的兜底轮询机制**。结合周边代码，我来完整解释它的作用。

## 一、它解决什么问题

聊天回复本来是通过 **SSE 流**实时接收的，收到 `done` 事件就代表生成结束（见 [consultation.vue:455-467](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L455-467)）。但存在两种"**本页面没有持流**"的情况：

1. **刷新页面后**：SSE 连接已断开，但服务器上回复可能还在生成中（后端用了 `Sinks.Many` 热流 + 可重挂机制，连接断开不会取消生成，见项目约束 ADR 0009）。
2. **其他标签页发起了回复**：本标签页根本没建立过流。

这时前端不知道生成何时结束，`isAiTyping`（输入锁定）、会话列表的"生成中"徽标就得不到更新。所以需要向服务器轮询对齐真实状态。

## 二、函数逻辑逐行拆解

```js
const startActivePolling = () => {
    if (activePollTimer) return          // ① 防重入：已有定时器则直接返回
    activePollTimer = setInterval(async () => {
        try {
            const active = await getActiveReply()   // ② 每 3s 查一次服务器活跃状态
            if (!active || !active.sessionId) {     // ③ 服务器说"没有活跃回复"了
                const sid = activeReplySessionId.value
                isAiTyping.value = false            // 解除输入锁定
                activeReplySessionId.value = null   // 清除"生成中"徽标对应的会话 id
                stopActivePolling()                 // ④ 停止轮询
                if (sid != null && currentSession.value?.sessionId === 'session_' + sid) {
                    refreshSessionView(sid)         // ⑤ 若刚结束的是当前查看的会话 → 拉最新消息+情绪卡片
                }
                getSessionPage()                    // ⑥ 刷新会话列表（去掉"生成中"徽标）
            }
        } catch {
            // 查询失败：下个周期重试（不停止轮询）
        }
    }, 3000)
}
```

关键设计点：

- **① 防重入**：`activePollTimer` 已在则直接返回，避免多个 `setInterval` 叠加（比如 `restoreActiveReply` 在页面加载和流异常时都可能触发）。
- **③ 结束条件**：只有"查询成功且明确返回没有活跃回复"才收尾。查询**失败**（catch）时反而继续轮询——因为失败可能是网络抖动，下个周期再试更稳妥，避免误判。
- **⑤ 数据回填**：`refreshSessionView` 调用 [refreshSessionView](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L733-737) 重新拉取会话消息和情绪卡片，把生成完成的内容补全到界面；但仅在"该会话正是当前正在查看的会话"时才做，防止错位刷新别的会话。
- **⑥ 列表刷新**：`getSessionPage()` 让侧栏的"生成中"红色徽标（[L89](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L89)）消失。

## 三、它如何被触发/停止

**启动入口**：`restoreActiveReply()`（[L719-731](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L719-731)），它在三个场景被调用：

- `onMounted`（刷新/新开标签页后，见 [L790](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L788-792)）；
- SSE 的 `onerror`（本地连接异常但服务器可能仍在生成，[L490-493](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L490-493)）；
- SSE 返回 409 单活跃流守卫错误（说明活跃回复来自其他标签页，[L478-484](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L478-484)）。

**停止入口**：`stopActivePolling()`（[L766-771](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L766-771)），除了轮询自查到结束会停止外，用户手动点"停止生成"（`handleStop`）、删除会话等操作也会主动调用它。

## 四、一句话总结

> **它是"本标签页没握住 SSE 流"时的状态同步兜底**：每 3 秒向服务器问一次"还有没有回复在生成"，一旦生成结束就解除输入锁定、清掉"生成中"徽标，并回填当前会话的最新消息。本标签页自己发起的流因为有 `done` 事件收尾，完全不需要走轮询。

## 场景复现

刷新后（或重新进入页面）→ `restoreActiveReply` 查到会话 42 正在生成 → `isAiTyping = true`、`activeReplySessionId = 42`。此刻你停在新对话界面，**对会话 42 没有任何流**。

## 没有轮询时，你会被锁多久？

**直到你手动做两件事之一**，而不是等到生成结束：

1. **点进会话 42** → `handleSessionClick` 触发 `attachActiveReply(42)`（[L648-651](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L648-651)）→ 拿到流 → `done` 事件解锁；
2. **点"停止生成"** → `handleStop` 主动清状态解锁。

关键点：**即使服务器上生成已经完成，你的锁也不会自己解开**。因为解锁靠的是前端收到 `done` 事件或主动操作——你不持有流，就永远收不到 `done`。轮询的意义就是把这个"完成"事件在 3 秒内替你查到并收尾。

## 三个容易误解的细节

**① 锁是全局的，不只是会话 42。** `isAiTyping` 是个布尔值，不是按会话区分的。你在"新对话"里发消息同样被 [sendMessage](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L327-330) 挡住，提示"有一条AI回复正在生成中"。所以你不只是"不能操作会话 42"，而是**整个聊天功能都不能发消息**。

**② 点别的会话不会解锁。** 点击会话本身不受 `isAiTyping` 拦截（导航是自由的，ADR 0009），但点进非活跃会话不会 attach（[L648](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L648) 的条件是 `activeReplySessionId === session.id`），也就没有 `done` 可收——锁依然在。

**③ 点进会话 42 不一定非得等它生成完才解锁。** 分两种情况，两种情况都能解：

| 点击时机 | 行为 | 解锁方式 |
|---|---|---|
| 生成**还在进行** | attach 成功 → 回放+实时续收 | 收到 `done` 事件 |
| 生成**恰好已完成** | attach 返回 404 → 走兜底分支（[L578-591](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L578-591)） | 直接清锁 + `refreshSessionView` 拉全量消息 |

## 一句话总结

> 是的：**不在活跃会话界面 → 不持有流 → 收不到 done → 没有轮询就是永久锁定**，而且这个"永久"连"生成结束"都等不到，只能靠你主动点进那个会话或点停止来解除。轮询补的正是这条"无人触发收尾"的漏洞。


用户问：如果有活跃会话，restoreActiveReply上锁，轮询机制解锁？
对，你理解得完全正确。这正是 `restoreActiveReply` 和 `startActivePolling` 的分工：

```
restoreActiveReply  →  上锁（isAiTyping=true + 点亮徽标）
startActivePolling  →  解锁（isAiTyping=false + 清徽标 + 回填消息 + 刷新列表）
```

只不过解锁有**前提**：轮询不是"一到 3 秒就解锁"，而是每 3 秒查一次 `/stream/active`，**只有查到"没有活跃回复了"才解锁**（[L750-756](file:///d:/Coding/health-agent/HealthAgent/ai-vue/src/views/consultation.vue#L747-757)）。查询失败则继续锁着重试。

用生命周期串一遍：

```
活跃回复生成中
  ├─ 刷新
  │   └─ onMounted → restoreActiveReply 查到"有活跃" → 🔒上锁 + 启动轮询
  └─ 等待……
      └─ 轮询每3s问一次 /stream/active
          ├─ 还在 → 继续锁，等下个周期
          └─ 不在了（生成结束、槽位已释放） → 🔓解锁 + 清徽标 + refreshSessionView回填 + getSessionPage
```

所以一句话：**`restoreActiveReply` 负责把"生成中"的锁从服务器「带」回本地，轮询负责在"生成结束"后把锁解开。** 一开一合，闭合了"刷新后无流也正确收尾"的闭环。

（补充：能解锁的不止轮询——本标签页自己 attach 接到流时靠 `done` 事件收尾；用户点"停止生成"也解锁。轮询只是"无流场景"的解锁通道。）
